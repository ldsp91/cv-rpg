## Server

- Command: `bun --hot index.ts` (equivalently `bun run dev`)
- URL: http://localhost:3000 (port source: assumption — `index.ts` sets no port; 3000 is `Bun.serve`'s default, confirmed listening during verification)
- Health check: `curl -sf http://localhost:3000 -o /dev/null`
- Reachability notes: a single route, `/`, serves `index.html`; there are no other routes and no API endpoints. `--hot` enables HMR, so edits under `src/` or `data/` live-reload the page. If a dev server is already running on :3000 (the health check passes immediately), reuse it — do not start a second one.

## Gotchas

- The 2026-09-18 run observed `bun install` exiting non-zero on the `quartermaster` devDependency (a path on the original developer's machine). That did not reproduce on 2026-09-19 with bun 1.4.2, which ignores `package.local.json` entirely — `bun install` and `bun install --frozen-lockfile` both exit 0. If a future bun version merges the file again, the install will fail in any environment without `/Users/levent/agents/quartermaster-cli`; the Pages workflow (`oven-sh/setup-bun@v2` → latest bun) is sensitive to that. (re-verified 2026-09-19 in a clean clone)
- `index.ts` sets no port; the server binds 3000 by framework default. Anything else already listening on :3000 will block the dev server from starting. (verified: :3000 was free and the server bound it)
- The split is structural, per ADR-0003: Phaser owns `#game` (booted once), React owns `#ui`. Automated tests must not re-render or replace `#game`; the canvas only exists after the page's JS has run. (verified in this run: `#game canvas` present, `#ui` holds the React overlay)
- `data/career.json` is statically imported (inlined into the bundle) — editing it requires the dev server to be running with HMR, or a page reload, to take effect. (inferred from `docs/STACK.md` and `career.test.ts` importing the file)
